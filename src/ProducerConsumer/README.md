# 🔄 Παραγωγός - Καταναλωτής (Producer - Consumer)

Κλασικό παράδειγμα συγχρονισμού νημάτων στη Java. Ένα νήμα **Παραγωγός** προσθέτει στοιχεία σε έναν κοινόχρηστο **Buffer** περιορισμένης χωρητικότητας και ένα νήμα **Καταναλωτής** τα αφαιρεί. Ο συγχρονισμός γίνεται με `synchronized`, `wait()` και `notifyAll()`.

---

## 📂 Αρχεία

| Αρχείο | Περιγραφή |
| :--- | :--- |
| **`Buffer.java`** | Ο κοινόχρηστος πόρος. Ουρά με μέγιστη χωρητικότητα. Οι μέθοδοι `produce()` / `consume()` μπλοκάρουν όταν το Buffer είναι γεμάτο / άδειο. |
| **`Producer.java`** | `Runnable` που παράγει 10 ακέραιους (ένα κάθε 100ms). |
| **`Consumer.java`** | `Runnable` που καταναλώνει 10 ακέραιους (ένα κάθε 500ms - πιο αργός από τον Παραγωγό). |
| **`ProducerConsumerDemo.java`** | Η `main`: δημιουργεί το Buffer και τα δύο νήματα, τα ξεκινά και περιμένει να τελειώσουν. |

Τα αρχεία ανήκουν στο πακέτο `producerconsumer`, άρα πρέπει να βρίσκονται σε φάκελο με το ίδιο όνομα:

```

|-- README.md
|-- producerconsumer/
    |-- Buffer.java
    |-- Consumer.java
    |-- Producer.java
    |-- ProducerConsumerDemo.java
```

Όλες οι εντολές εκτελούνται από τον φάκελο `ProducerConsumer` (αυτόν που **περιέχει** τον φάκελο `producerconsumer`).

### 1. Μεταγλώττιση

```bash
javac -d . producerconsumer/*.java
```

Το `-d .` λέει στον `javac` να τοποθετήσει τα `.class` αρχεία στον τρέχοντα φάκελο, διατηρώντας τη δομή του πακέτου (δηλαδή μέσα στο `producerconsumer/`).

### 2. Εκτέλεση

```bash
java producerconsumer.ProducerConsumerDemo
```

Προσοχή: δίνουμε το **πλήρες όνομα** της κλάσης (`πακέτο.Κλάση`), όχι διαδρομή αρχείου.

## ❓ Γιατί τα πεδία του Buffer είναι `final`;

```java
private final Queue<Integer> list = new LinkedList<>();
private final int capacity;
```

Αυστηρά, το πρόγραμμα θα δούλευε και χωρίς `final`. Είναι όμως καλή πρακτική για πεδία που μοιράζονται πολλά νήματα:

1. **Η αναφορά δεν αλλάζει ποτέ.** Ο compiler δεν επιτρέπει να γράψει κανείς κάπου `list = new LinkedList<>()`. Αν συνέβαινε αυτό ενώ τρέχουν τα νήματα, ο ένας θα μπορούσε να γράφει σε μια ουρά και ο άλλος να διαβάζει από μια άλλη. Με το `final` όλα τα νήματα δουλεύουν πάντα στο **ίδιο** αντικείμενο.

2. **Ασφαλής ορατότητα (safe publication).** Το Java Memory Model εγγυάται ότι μόλις ολοκληρωθεί ο constructor, **κάθε** νήμα βλέπει τις σωστές τιμές των `final` πεδίων χωρίς επιπλέον συγχρονισμό. Χωρίς `final`, ένα νήμα θα μπορούσε θεωρητικά να δει `capacity == 0` ή `list == null`. (Στο συγκεκριμένο πρόγραμμα αυτό δεν συμβαίνει, επειδή το `Thread.start()` εγγυάται ήδη ότι το νέο νήμα βλέπει ό,τι έγινε πριν από αυτό.)

3. **Δηλώνει πρόθεση.** Όποιος διαβάζει τον κώδικα καταλαβαίνει αμέσως ότι το πεδίο ορίζεται μία φορά και δεν αλλάζει.

> ⚠️ **Συνηθισμένη παρανόηση:** το `final` κλειδώνει την **αναφορά**, όχι το **περιεχόμενο**. Η ουρά αλλάζει κανονικά με `list.add(...)` και `list.poll()`. Άρα το `final` **δεν** κάνει την ουρά thread-safe - γι' αυτό χρειαζόμαστε ακόμα το `synchronized`.

## 🧪 Ασκήσεις

Κάντε κάθε αλλαγή, τρέξτε το πρόγραμμα και εξηγήστε τι παρατηρείτε.

1. **Χωρίς `synchronized`.** Αφαιρέστε τα μπλοκ `synchronized (this)` από το `Buffer`. Τι συμβαίνει και γιατί;
   *(Υπόδειξη: `IllegalMonitorStateException` - οι `wait()` / `notifyAll()` απαιτούν να κατέχουμε την κλειδαριά.)*

2. **`if` αντί για `while`.** Αλλάξτε το `while` σε `if` γύρω από τα `wait()` και δημιουργήστε **2 καταναλωτές**. Τι μπορεί να πάει στραβά;
   *(Υπόδειξη: ένας καταναλωτής ξυπνά, αλλά άλλος έχει ήδη πάρει το στοιχείο → `poll()` επιστρέφει `null` → `NullPointerException`.)*

3. **`notify()` αντί για `notifyAll()`.** Χρησιμοποιήστε `notify()` με **2 παραγωγούς και 2 καταναλωτές**. Τρέξτε το αρκετές φορές. Κολλάει ποτέ το πρόγραμμα; Γιατί;
   *(Υπόδειξη: ένας καταναλωτής μπορεί να ξυπνήσει άλλον καταναλωτή αντί για παραγωγό.)*

4. **Ασύμμετρο πλήθος.** Ο Παραγωγός παράγει 10 στοιχεία αλλά ο Καταναλωτής προσπαθεί να καταναλώσει 15. Τι συμβαίνει; Προτείνετε τρόπο ώστε ο Καταναλωτής να καταλαβαίνει ότι δεν θα έρθουν άλλα στοιχεία.
   *(Υπόδειξη: τεχνική «poison pill» - μια ειδική τιμή, π.χ. `-1`, που σημαίνει «τέλος».)*

5. **Ταχύτητες και χωρητικότητα.** Αλλάξτε τα `Thread.sleep()` ώστε ο Παραγωγός να είναι πιο αργός από τον Καταναλωτή. Πειραματιστείτε επίσης με τη χωρητικότητα (`new Buffer(1)`, `new Buffer(20)`). Πώς αλλάζει η έξοδος;

6. **`ReentrantLock` και `Condition`.** Υλοποιήστε το `Buffer` με `ReentrantLock` και δύο `Condition` (`notFull`, `notEmpty`) αντί για `synchronized` / `wait()` / `notifyAll()`. Γιατί αυτή η λύση ξυπνά μόνο τα νήματα που πραγματικά χρειάζεται;

7. **`BlockingQueue`.** Αντικαταστήστε ολόκληρο το `Buffer` με ένα `ArrayBlockingQueue<Integer>` και τις μεθόδους `put()` / `take()`. Συγκρίνετε τον κώδικα - αυτό χρησιμοποιούμε στην πράξη.
